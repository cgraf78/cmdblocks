# AGENTS.md

## About

`cmdblocks` is three self-contained Bash commands for tmux: copying recent
command output (`tmux-copy-last-output`), ringing the bell and marking the
pane (`term-notify-sound`), and pane state marks (`term-pane-mark`). The
README is the user guide; each command's man page holds the detailed
behavior.

## Layout

- `bin/`: the three commands. Each must stay self-contained.
- `man/man1/`: one page per command.
- `share/cmdblocks/shell.sh`: a no-op shell loader for integrators.
- `install.sh`: generated checkout installer (see below).
  `support/install-checkout.sh` holds the repo-owned link logic and its
  command list; `scripts/checkout-installer.conf` configures the generator.
- `test/cmdblocks-test`: runs every `test/suites/*-test`. Suites:
  `cmdblocks-behavior`, `install`, `manpage`, `shellcheck`, `ci-contract`;
  all but `shellcheck-test` source `test/helpers.sh` for assertions.

## Invariants

- `@term_notify_pending` and `@term_busy` (pane options set to `1`) are
  read by users' tmux configs. Don't rename them.
- `tmux-copy-last-output` parses one two-line prompt shape (header comment
  and awk patterns in the script). If the patterns change, update the
  README "Prompt format" section and the man page with them.
- Every command is best effort inside tmux: missing tmux, panes, or helpers
  must not turn the caller's work into an error. Exit 64 is reserved for
  bad arguments; `tmux-copy-last-output --print` exits 3 when it finds no
  block.
- `manpage-test` requires `man/man1/<cmd>.1` with `.SH NAME` and `<cmd> \`
  for every file in `bin/`. A new command also needs a row in
  `support/install-checkout.sh` and in the ShellCheck inventory.

## Testing

- Local: `test/cmdblocks-test`. `shellcheck-test` fails when `shellcheck` is
  missing; it does not skip.
- CI: `CMDBLOCKS_SKIP_SHELLCHECK=1 test/cmdblocks-test`, with the `base`
  profile only (no tmux, no ShellCheck) on the full platform matrix plus
  Termux, on every PR.

## Test isolation

- Behavior tests use a fake `tmux` on `PATH`, fixture capture files,
  synthetic `TMUX`/`TMUX_PANE`, and `TERM_PANE_MARK_PROC_ROOT` in place of
  `/proc`. There is no real tmux in CI; keep tests independent of one.
- If a manual check needs a real tmux, use a private server
  (`tmux -S <tmpdir>/sock -f /dev/null` with `TMUX` unset), kill it
  afterwards, and never touch the default server.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale
  rows; local `test/cmdblocks-test` does not detect this. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`,
  where `<actions@lock>` is a cgraf78/actions checkout at the SHA in
  `.github/cgraf78-actions.lock`.
- `install.sh` is generated by cgraf78/actions checkout-installer and
  byte-checked by `actions-sync`; never edit it. Install logic lives in
  `support/install-checkout.sh`. After editing
  `scripts/checkout-installer.conf`, run `consumer-ci/sync.sh <this checkout>`
  from a cgraf78/actions checkout at the SHA in
  `.github/cgraf78-actions.lock`.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@sha`
  move together, only via `consumer-ci/sync.sh`.
- `test/suites/ci-contract-test` pins `test.yml` (`profiles: base`, the
  `test-command`, the inventory path, the `actions-sync` job shape) and the
  lock SHA in the retry and Dependabot workflows. Edit it together with
  them.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't rename
  it.
